# 卢氏龙虎趋势池

这是一个面向沪深 A 股的数值公式筛选与趋势跟踪网站。名单由完整收盘数据确认；交易时段约每 5 分钟更新最新价、涨跌、主选区、次选区及风险状态。主选区仅作观察，次选区执行冻结生产策略；ST、*ST 不进入主选区、次选区或观察区。

## 筛选口径

- 可能见底：最近 5 个交易日出现信号。
- 龙腾跃虎：龙线从下向上穿过虎线，且当前龙线仍在虎线上方。
- 近期涨停：最近 42 个交易日至少出现一次收盘涨停。
- 公式黄柱：龙线高于开盘价与收盘价中的较低者，K 线实体位于龙线下方的部分显示为黄色。
- 有效黄柱：龙腾跃虎发生日前 2 个交易日至发生后 7 个交易日内，至少出现 1 根公式黄柱。
- 主选区：可能见底、龙腾跃虎、近期涨停、有效黄柱四项同时满足。
- 次选区：龙腾跃虎和有效黄柱同时满足，并在可能见底、近期涨停中至少再满足一项；`selected=false`。
- 观察区：仅用于展示接近条件的标的，不计入入选或收益。观察区黄柱独立识别，不要求先有龙腾跃虎。

## 买卖与状态

主选与次选采用不同用途：主选只观察，不生成自动买卖或生产绩效；次选按一条完整状态链推进：

策略切换前已经建立的主选持仓不会从页面消失：它们单列为“策略切换前持仓”，仅沿用旧卖点完成存量退出，不计入主选当前信号数量，也不进入次选新策略绩效。

1. 首次进入次选只形成候选，显示“待观察中 / 等待买入”。
2. 在首次进入次选后的第 2 个完整交易日收盘检查：信号仍有效、龙线仍高于虎线、收盘不低于龙线、龙线不低于前一日，且较信号日收盘回撤不超过 3%。全部满足才确认买点，下一可交易日开盘执行买入；执行最多等待 5 个交易日。
3. 候选期间若信号被逐日重算抹去，则取消候选，不产生买点，也不计成功率。
4. 买入后正常显示“上升趋势中 / 继续持有”；转弱但尚未触发卖点时显示“谨慎持有中 / 风险观察”。
5. 信号在可见窗口内被重算消失，或龙线不再高于虎线时优先确认卖点；否则在浮盈达到 10% 后较最高收盘回撤 10%，或龙虎线连续三点同步转弱时确认卖点，最晚跟踪 60 个后续交易日。
6. 卖点收盘确认后在下一可交易日开盘执行；实际卖出前仍属于次选跟踪池，不提前结算。执行卖出后才计入次选已结束成功率与收益；同一股票以后形成新信号时可以重新进入。

盘中只提供临时判断；正式名单、买卖触发和结算均以完整收盘数据确认。具体买点、卖点阈值及执行假设由最新联合滚动验证 JSON 驱动，网页不另写一套固定口径。

## 联合滚动验证

买点与卖点在同一个逐日状态机中共同验证，每一天只能使用当时已经存在的数据：

- 主选区只报告入选信号数量，不展示自动买卖、成功率或收益率；生产绩效只统计次选区。
- `live_strategy_id` 标识实时执行合同，`frozen_candidate_id` 标识本轮冻结回测候选，两者分开读取，禁止缺失时静默改用其他候选。
- 网站操作提示、正式案例和次选绩效必须绑定同一冻结候选。严格按开发阶段选出的其他候选只作为“未启用的研究对照”，不会自动改变操作提示。
- 基础“龙虎交叉 + 有效黄柱”只作为研究层，不代表主选区或次选区绩效。
- 数据截止到已完成交易日，盘中未完成日 K 不进入回测。
- 收盘确认买卖触发，下一可交易日开盘模拟成交；候选取消、买点待执行、卖点待执行和完整交易分别记录。
- 成功率只统计已经完整执行买入与卖出的交易。历史联合回测收益按 JSON 记录的费用和滑点假设计算净收益；实时跟踪只显示价格收益，未扣用户账户实际费用。
- 案例仅在 `run_id`、`config_hash`、`completed_trade_date`、`frozen_candidate_id` 四项与联合验证完全一致时展示。
- 可选仓位验证仅在数据截止日、次选执行范围和冻结候选身份一致时展示；正式候选在 1× 基准费用下比较 5/10/20 个“等槽位建仓、不再平衡”的组合，展示 7 组固定排序中整体收益最差一组的账户 CAGR、最大回撤、平均敞口和容量拒绝。容量排序只使用买入时已知的股票、信号日、买入日和固定种子，不读取未来卖出日期。
- 收益优先纯 10/10 候选只展示为 20 槽位研究对照。它带来的少量账户 CAGR 增益伴随更深最大回撤，不驱动实时操作；“2×”只放大佣金与滑点，法定经手费、证管费和印花税仍按基准值计算。
- 单笔成功率与平均收益只统计后续至少 72 根 K 线且已完成卖出的共同样本；组合曲线则纳入截止日前所有实际成交的买入，不预先筛除未来卖不掉的股票。尚未触发卖点或卖出受阻的持仓继续占用槽位，并在截止日按最近收盘价估值。
- 账户 CAGR 是包含空仓、并发持仓、容量限制和资金利用率的组合资金曲线指标，不是单笔成功率，也不能替代单只股票平均收益。2026 是已被查看过的历史时间段，真正的 forward 验证从冻结截止日之后开始。

法定费用参考包括卖方印花税 0.5‰、经手费 0.0341‰双边和证管费 0.02‰双边；佣金、滑点属于回测假设，并非法定标准。回测未模拟按笔最低 5 元佣金和真实冲击成本。参考：[深交所收费标准](https://www.szse.cn/marketServices/deal/payFees/index.html)、[财政部、税务总局印花税公告](https://shanghai.chinatax.gov.cn/tax/zcfw/zcfgk/yhs/202308/t468451.html)。

## 自动运行与发布

仓库的 GitHub Actions 可独立运行，不依赖个人电脑，也不调用 Codex 或 OpenAI：

- `Intraday market refresh`：交易时段读取全市场最新开高低收，更新盘中名单、价格、涨跌与风险状态，不提前结算。
- `Daily close screening`：收盘数据稳定后保存正式名单、状态和事件；休市日不推进交易状态。
- `Weekly rolling validation`：每周在已完成交易日数据上重新执行买卖点联合滚动验证，并刷新网站完整历史验证区。

网页由 GitHub Pages Actions 部署。`cloud_snapshot.json` 保存收盘后的数值种子，盘中更新不依赖图片形态识别。

## 主要文件

- `config.json`：筛选窗口与黄柱要求。
- `results/latest.html`：最近生成的网站页面。
- `results/live.json`：盘中行情、名单和跟踪状态。
- `results/strategy_grid_optimization.json`：当前联合滚动验证、次选冻结候选绩效和执行假设。
- `results/strategy_portfolio_validation.json`：次选 5/10/20 槽位仓位压力情景及费用敏感性对照。
- `results/trend_case.json`：由正式交易记录生成的合法案例及候选取消反例。
- `strategy/state.json`：次选生产状态及历史迁移记录，请勿手工删除或修改。
- `report_ui.py`：网站的单一渲染入口。
- `refresh_report_research.py`：联合验证完成后刷新现有报告中的研究区。

## 手工运行

在 PowerShell 运行：

```powershell
.\run_daily.ps1
```

建议在交易日收盘数据稳定后运行，例如 15:20 以后。程序会拒绝用过早的盘中日线更新正式日报和策略状态；节假日运行会保留最近一个交易日结果。

## 数据边界

- 自动扫描覆盖沪深 A 股；北交所暂未纳入。
- ST、*ST 按当时可取得的证券名称排除；历史名称数据仍可能存在边界误差。
- 免费公开行情适合个人研究和小范围分享；商业化服务应更换有授权的数据源。
- 本项目是技术条件筛选，不构成投资建议，也不承诺收益。
